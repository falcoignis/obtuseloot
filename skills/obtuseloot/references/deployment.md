## Installation once the path is authorized

1. Build from a recorded GitHub tag or commit. Inspect the JAR and verify JDBC driver availability for the selected storage backend; do not assume drivers are bundled.
2. Record its SHA-256. Published releases use `v`-prefixed tags through `release.yml`.
3. Review the storage backend, autosave interval, telemetry/analytics output paths and permissions for the target. Keep credentials outside the repository.
4. Verify storage failure behavior against the decision ledger: fatal at startup, per-player refusal/retry at runtime, failed saves retained as dirty. Never treat failed loads as missing records.
5. Keep `webServerEnabled: false` while the unauthenticated dashboard HTTP server remains in the code. Its removal is an owner decision.
6. At first boot, check persistence initialization, telemetry rehydration and listener registration. Check that a non-op can use `/ol help` and privileged commands retain explicit permission checks.
